ABSTRACT

LuxeCart E-Commerce Website is a full-stack web application developed to provide a modern online shopping experience with both customer-facing and administrator-facing functionality. The system allows customers to browse products by category, search the catalog, view product details, manage carts and wishlists, store delivery addresses, place orders, review order history, and raise support tickets. The application also includes a dedicated admin workspace to manage products, store sections, customer users, support tickets, order details, and key sales insights.

The project is implemented using Angular and TypeScript for the frontend, Bootstrap for responsive interface design, Express.js for the backend API, and MySQL for persistent relational data storage. The application follows a layered architecture where the user interface communicates with secure API endpoints, and the backend performs validation, business logic, and database operations. Additional modules handle customer authentication, admin authentication, order recording, masked payment card storage, and support ticket workflows.

The project demonstrates how a scalable e-commerce platform can be built using modern web technologies while keeping the interface practical and user friendly. It improves shopping efficiency, simplifies store management, and provides a structured foundation for future enhancements such as online payment gateway integration, delivery tracking, recommendation systems, and production deployment.

1. INTRODUCTION

1.1 Overview of the System

LuxeCart is a web-based e-commerce management system created to provide both an attractive shopping platform for customers and an operational control center for administrators. The system supports browsing products across multiple store sections, searching by category, viewing detailed product cards, placing orders, and following order history. On the administration side, the system provides product management, section management, customer account handling, support ticket handling, and sales overview features.

The frontend is designed to be responsive and interactive, with customer pages such as home, collections, product detail, checkout, confirmation, orders, account, sign-in, sign-up, and support. The admin module introduces a separate workspace where product details, purchased details, best-performing products, support requests, stock visibility, and user information can be monitored efficiently.

The backend validates user input, processes orders, stores support requests, manages admin sessions, and maintains structured data in MySQL tables. This integration provides a complete commerce workflow from catalog display to order storage and post-purchase support.

1.2 Specific Objectives

  • To develop a full-stack e-commerce website using Angular, Express.js, and MySQL.
  • To provide customer authentication with account, password, and recovery features.
  • To implement product browsing, category filtering, search, wishlist, and cart management.
  • To design a checkout process with delivery address capture and masked card-detail support.
  • To store orders, order items, customer records, and support requests in a relational database.
  • To build an admin dashboard for products, sections, users, orders, revenue, and support management.
  • To create a responsive interface suitable for both desktop and mobile usage.

2. SYSTEM STUDY AND ANALYSIS

2.1 Existing System

In many basic online shopping systems, the customer view and administrator workflow are separated poorly or handled manually. Older systems often depend on static product listings, limited search, and weak order tracking. Support management is frequently handled outside the system, and customer account recovery or profile updating is not integrated into the application itself.

Common limitations in existing systems include:

  • Limited filtering and search support across multiple categories.
  • No unified admin panel for products, orders, users, and support operations.
  • Weak checkout validation and incomplete order history tracking.
  • No structured storage for support tickets and customer account data.
  • Poor separation between customer features and admin operations.
  • Lack of responsive, modern interface behavior for real-time usage.

2.2 Proposed System

The proposed LuxeCart E-Commerce Website addresses these issues by introducing an integrated shopping and store administration platform. The customer module supports authentication, cart handling, saved addresses, order confirmation, account management, and support ticket submission. The admin module provides analytics, section editing, product editing, user review, and ticket management in one workspace.

Key features of the proposed system include:

  • Responsive Angular storefront for customers.
  • Search and category-based product discovery.
  • Wishlist, cart, and “buy now” purchase flow.
  • Customer account registration, login, profile update, and password recovery.
  • Checkout form with order validation and masked card detail capture.
  • Order history, latest order details, and recent ordered product views.
  • Support ticket creation and support history tracking.
  • Admin login with role-based access for store control features.
  • Admin dashboard showing revenue, top products, users, and order details.
  • Product, section, support, and customer management with MySQL persistence.

3.3 Software Profile

The system is built using a three-layer architecture consisting of frontend presentation, backend application logic, and relational data storage. Angular is used to create reusable components for product cards, checkout, orders, admin pages, and support pages. TypeScript improves maintainability through typed models and structured component logic.

Express.js is used on the server side to define REST API endpoints for products, sections, orders, user authentication, admin authentication, support tickets, customer lists, and dashboard analytics. Input validation and error handling are implemented in route-level processing before data is stored or returned to the client.

MySQL acts as the persistent relational database. It stores store sections, products, orders, order items, support tickets, admin accounts, customer accounts, and card detail summaries. This structured storage model ensures organized retrieval, reporting, and future scalability.

Bootstrap and custom CSS are used to create a responsive visual interface. The application additionally supports Indian currency display, toast-based notifications, and consistent UX behavior across the customer and admin modules.

4. SYSTEM DESIGN

4.1 Data Flow Diagram

The system follows a request-response model. Customers and administrators interact with the Angular frontend. The frontend sends requests to the Express API, and the API communicates with the MySQL database to read or store product, account, order, and support data.

Level 0 Data Flow Description:

  1. Customer/Admin enters request through the frontend user interface.
  2. Frontend sends validated request to backend API endpoints.
  3. Backend processes business logic and communicates with the MySQL database.
  4. Database returns data or stores updated records.
  5. Backend sends the processed result back to the frontend for display.

Main external entities: Customer, Admin, Database.

Main processes: Authentication, Product Management, Order Processing, Support Processing, Admin Reporting.

4.2 Database Design

The database is designed to maintain structured commerce data with clear relationships between products, orders, users, support requests, and admin activities.

Table Name Purpose Important Fields
store_sections Stores product section names and display order. id, name, sort_order, created_at
products Stores product catalog data. id, name, category, description, image_url, price, rating, stock, featured, badge
orders Stores placed order summary and customer delivery details. id, order_reference, customer_name, email, phone, payment_method, subtotal, total_amount, status, created_at
order_items Stores individual ordered products under each order. id, order_id, product_id, product_name, quantity, unit_price, line_total
support_tickets Stores customer support issues and admin replies. id, customer_name, email, order_reference, issue_type, subject, message, status, admin_response
admin_accounts Stores admin and sub-admin credentials with role information. id, name, email, phone, password_hash, password_salt, role
customer_accounts Stores registered customer authentication and profile data. id, name, email, phone, password_hash, password_salt, password_hint, created_at
card_details Stores safe masked card information for card payment history. id, account_email, cardholder_name, card_last4, expiry, card_brand

5. IMPLEMENTATION

Implementation is the stage where the system design is transformed into a working web application. LuxeCart is implemented using modular frontend and backend components so that customer workflows and admin workflows can be maintained independently while sharing the same database and API layer.

5.1 Frontend Module

The frontend is built in Angular with reusable components for home hero sections, product cards, collection grids, order summaries, support cards, account forms, and admin lists. Routing is handled within the application view logic, and responsive design is achieved through Bootstrap and custom CSS.

5.2 Authentication Module

The system supports customer sign-up, customer login, password hint verification, password reset, and admin login. Session information is stored locally for a smoother user experience. Toast notifications are used to inform users about success and error states.

5.3 Commerce Module

Products can be browsed, searched, filtered by section, added to the cart, moved to saved items, or placed through the instant checkout flow. The checkout module validates customer details, address data, delivery fee, and payment method before submitting the order.

5.4 Admin Module

The admin workspace includes overview metrics, recent purchased details, best-performing products, section management, product creation and editing, customer user review, sub-admin control, stock monitoring, and support ticket status management.

5.5 Database and Seed Module

The backend contains schema setup, product seed logic, and migration support for newer tables such as customer accounts and card details. Product images are managed through seeded image pools, and order information is stored in normalized tables for reporting and historical lookup.
